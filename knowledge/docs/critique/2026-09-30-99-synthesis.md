# Devil's Advocate 종합 — knowledge 플러그인

작성 2026-09-30, 대상 v1.19.1. 입력: 기준 의견 1건 + 페르소나 4건(같은 디렉터리 00~04).

| 파일 | 페르소나 | 핵심 취약점 |
|---|---|---|
| 00-baseline | 기준 | 신뢰가 N=1(WMS 볼트, 94문항) 위에 서 있다 — 내적 타당성만 있고 외적 타당성이 없다 |
| 01-ir-researcher | IR/NLP 연구자 | 한국어 매칭·융합 가중치(0.7/0.3, 승격 0.35)가 ablation 없는 휴리스틱인데 헤드라인 수치가 거기서 나왔다 |
| 02-end-user | 실사용자 팀 리드 | 볼트가 유지되는 자산이 아니라 일회성 프로젝트다 — 갱신 장치 없음, 인프라는 사용자 몫 |
| 03-maintainer | 유지보수자 | 유일한 안전망인 테스트가 CI 밖이고 튜닝 상수를 고정하지 않는다. 단독 저자 |
| 04-competitor | 경쟁 제품 PM | "볼트 없이 하면 안 되나?"에 답하는 기준선이 없다 |

## 수렴한 반론 (2개 이상 페르소나가 독립적으로 지목)

**A. 비교 기준선이 없다** — 00(단일 코퍼스), 01(hash 대비만, BM25/임베딩 단독 비교 없음), 02(grep 대비 없음),
04(볼트 없는 agentic 검색 대비 없음). 네 방향 모두 "무엇보다 나은가"를 묻는다. 저장소 자체 측정에서 에이전트
검색이 93/94에 정답 노트에 닿았다는 사실(ROADMAP 2026-08-31)이 이 질문을 더 날카롭게 만든다.

**B. 측정 결론이 통계적으로 약하다** — 00(재실행 대기 중 변경 누적), 01(다중비교 보정 없음, holdout ~33문항,
동점 버리는 부호 검정, Dwork 인용만 있고 구현 없음), 03(상수 변경이 SCHEMA_VERSION·baseline 비교를 무효화).

**C. 볼트가 시간에 따라 유지되지 않는다** — 00(소스 드리프트를 eval이 구조상 못 봄), 02(훅은 `.md` 편집에만
반응하고 큐 5개에 기록만 한다. **큐 소비자 없음 — 직접 확인**: 큐 파일명을 hooks/ 밖에서 참조하는 파일 0건).

**D. 튜닝 상수가 검증 없이 쌓였다** — 01(ablation 없음), 03(최상위 상수 27개가 서로 얽혀 있고 테스트가 하나도
참조하지 않음, 2,144줄 단일 파일).

## 직접 확인한 사실
- CI(`.github/workflows/validate-plugins.yml`)는 `python3 _repo/scripts/validate_plugins.py`만 돌린다. `node --test` 없음.
- 로컬 Node는 v22.12.0 — 03에 따르면 `node:sqlite` 로드 실패로 `sqlite-knowledge.test.mjs` 45개 전부 실행 불가.
- 매니페스트 버전은 1.19.1.

## 단일 핵심 취약점
**이 플러그인은 자기 자신 말고는 아무것과도 비교된 적이 없다.** 볼트 없는 방식, 다른 코퍼스, 남이 쓴 질문,
시간이 지난 소스, 다른 상수값 — 어느 축에서도 대조군이 없다. 정교한 내부 측정 규율(부호 검정, incomparable,
holdout)이 이 공백을 가린다. A~D는 전부 이 한 문장의 다른 얼굴이다.

## 가역성
reversible — 스킬·문서·기본값이라 되돌릴 수 있다. 되돌리기 어려운 건 사용자가 볼트 작성에 쓴 시간과 팀의
신뢰(02, 04), 그리고 상수가 바뀔 때마다 무효가 되는 과거 측정(03).

## 나아갈 방향 (우선순위)
1. **안전망부터 (1일 이내)** — CI에 `node --test` + Node ≥ 22.13(또는 `node:sqlite` 지원 버전) 고정.
   튜닝 상수를 테스트가 참조하도록 golden 테스트 추가. 이게 없으면 이후 모든 변경이 무검증이다. (03)
2. **기능 동결 + 94문항 재실행** — v1.17~1.19 누적분의 기준선 재수립. (00·B)
3. **3자 기준선 벤치마크** — 같은 94문항에서 (a) 볼트 없이 원본 소스 agentic grep/read, (b) 볼트 + 검색,
   (c) 볼트 + 검색 + knowledge-query 규율. 인용 정확도·비용·시간. (a)와 차이가 없으면 플러그인의 가치 제안을
   "검색 엔진"에서 "답변 규율·감사 가능성"으로 옮긴다. (A·04·02)
4. **ablation 한 번** — BM25 단독 / 임베딩 단독 / 융합, 한국어 규칙 on/off, 승격 on/off. 효과 없는 상수는 삭제.
   스윕에 다중비교 보정. (01·D)
5. **두 번째 코퍼스 + 외부 질문 20~30개** — 기본값 이전성 확인. (00)
6. **갱신 루프를 닫거나 지운다** — 큐 소비자(drain 커맨드)를 만들든지, 소비자 없는 큐 쓰기를 제거하든지.
   소스 해시 기반 stale 검사로 드리프트를 수치화. (C·02)
7. 1~5 결과를 본 뒤 Phase 4b 여부 결정. (04)

1번과 6번의 제거 쪽은 동작 변경이므로 CLAUDE.md 규칙상 plan → 승인 후 착수. 2~5는 측정이다.

# deck-builder — 로드맵

작성 2026-10-12, portfolio 2.4.2 기준. 순서의 근거는 실제 사용자 템플릿(V35, 36 아키타입,
한글 NanumSquare) 한 벌로 측정한 값입니다. 픽스처로는 하나도 나오지 않던 것들입니다.

```
폭 추정 오차      템플릿 문장 411개 중 97%가 10% 이상 빗나감 (중앙값 +19%)
글자별 오차       한글 +10%   공백 +120%   마침표 +124%   숫자 -8%
줄 높이           추정 1.200 em  vs  실제 1.135 em (+6%)
고아 미디어       6장짜리 덱이 28.1MB를 끌고 다님 (실사용 0.9MB)
말투 지문         420문장: 명사형 47% · 했습니다 29% · 중앙값 44자 · 영문용어 46%
```

목표는 기능 추가가 아니라 **한 번에 맞추는 것**입니다. 지금은 쓰고 → 겹치고 → 줄이고 →
다시 렌더하는 루프가 돌고, 그 루프의 원인은 전부 "몇 글자가 들어가는지 모른다" 하나입니다.

---

## Phase 0 — build/ 분리 (완료, 이 커밋)

소스와 산출물을 디렉터리로 가릅니다. 컴파일러 모델을 내세우면서 빌드 디렉터리가 없던 상태를
정리하는 것이고, 뒤 Phase가 전부 이 레이아웃을 전제합니다.

```
<프로젝트>/
├── template.pptx     소스 · 툴체인
├── deck.mdx          소스 · 유일한 편집 대상
├── deck.scss         소스 · 스타일 (Phase 4)
├── assets/           소스 · 생성한 아트
└── build/            산출물 · 통째로 지워도 됨
    ├── deck.pptx  deck.pdf  catalog.md
    ├── pages/
    └── .cache/
```

`output:` 프런트매터는 그대로 우선합니다(기존 덱 호환). 기본값만 `build/`로 바뀝니다.

## Phase 1 — 실제 폰트 메트릭 ★ 나머지 전부의 전제

**상태 (2026-10-12): 구현됨.** `textN_plusK` 키로 (1) 같은 그룹의 같은 서식 형제 도형(3개 이상, 일정
간격) 또는 (2) 같은 서식의 반복 행 그룹(끝쪽 2개 이상, 마지막 간격, 간격 편차 10% 이내)을 K칸
복제합니다. 아니면 이유와 함께 거부합니다. V35 목차: 행 그룹 복제로 일곱째 행이 마지막 간격에
정렬되어 렌더됨. 슬라이드 하단 여유가 행 하나뿐이라 여덟째는 거부됩니다. 1·2행은 설명 박스가
없는 행이라 설명 6개짜리 목차는 이 템플릿으로 만들 수 없습니다.

범위를 좁게 잡을 것: **같은 서식의 형제 도형이 일정 간격으로 반복될 때만.** 임의 위치에
도형을 만드는 기능이 아닙니다. 그 선을 넘으면 "템플릿이 디자인 권위"가 무너집니다.

## Phase 4 — deck.scss (Phase 1 위)

mdx가 HTML이면 스타일시트가 있어야 합니다. 캐스케이드: **템플릿 → deck.scss → 인라인**.

SCSS에서 그대로 가져올 것:

```scss
$navy: #435EA0;  $accent: #E0533D;        // 토큰 = 변수
@s3 { text1 { color: $navy; } }            // 중첩 = 아키타입 > 슬롯
.metric { size: 40pt; weight: bold; }      // 역할 = @extend / mixin
```

**덱에만 있어야 하는 것 — CSS에 대응물이 없습니다:**

| | |
|---|---|
| `fit` 정책 | 웹에서 overflow는 선택이지만 덱에서는 결함. `fit: strict \| shrink \| wrap(n)` |
| 양방향 적합 | 덜 채우는 것도 결함. `min-fill: 0.6` |
| **배치 선언 금지** | 위치를 쓸 수 없음. 프레임은 템플릿 것 |

마지막 항목이 설계의 핵심 제약입니다. 이걸 열면 그냥 또 하나의 슬라이드 생성기가 됩니다.

파서는 자작(표준 라이브러리만). SCSS 전체가 아니라 위 네 가지 — 변수 · 중첩 · `@extend` ·
선언 — 로 범위를 닫습니다.

## Phase 5 — 재색상을 팔레트로 (Phase 4의 일부)

`scripts/ppt_keycolor_changer.py`는 **빌드된 pptx를 후처리**합니다. 이 스킬이 다른 모든
자리에서 금지하는 바로 그 행위입니다. 팔레트가 `deck.scss`로 들어가면 브랜드 색 변경이
"스타일시트 한 줄 + 재빌드"가 되고, 후처리 스크립트는 **소스가 없는 레거시 pptx 전용**으로만
남습니다. `references/recolor.md`도 그 범위로 좁힙니다.

## 영구 제외

- **네이티브 차트 쓰기** — 도식화(SVG)로 갑니다. 임베드 xlsx + 캐시 XML을 양쪽 다 써야 하는
  비용에 비해 얻는 게 없습니다.
- **임의 레이아웃 생성** — 템플릿에 없는 배치는 만들지 않습니다.

## 닫히지 않은 것

- **PowerPoint·Keynote 미검증.** 전부 LibreOffice 25.8 기준입니다. 호환성 관련 서술은
  측정이 아니라 추론입니다.
- **JPEG 디코딩 불가.** 투명 처리와 가독성 채점에서 빠집니다.
- **아키타입 id가 `s1..sN`.** `template_hash`가 조용한 부패는 막지만 소스 가독성은 그대로.
  슬라이드 제목에서 별칭을 뽑는 안이 있으나 우선순위 낮음.

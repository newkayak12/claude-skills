# deck-builder — 로드맵

작성 2026-10-12, portfolio 2.4.2 기준. 순서의 근거는 실제 사용자 템플릿(V35, 36 아키타입,
한글 NanumSquare) 한 벌로 측정한 값입니다. 픽스처로는 하나도 나오지 않던 것들입니다.

```
폭 추정 오차      템플릿 문장 411개 중 97%가 10% 이상 빗나감 (중앙값 +19%)
글자별 오차       한글 +10%   공백 +120%   마침표 +124%   숫자 -8%
줄 높이           추정 1.200 em  vs  실제 1.135 em (+6%)
고아 미디어       6장짜리 덱이 28.1MB를 끌고 다님 (실사용 0.9MB)
말투 지문         420문장: 명사형 47% · 했습니다 29% · 중앙값 44자 · 영문용어 46%
```

목표는 기능 추가가 아니라 **한 번에 맞추는 것**입니다. 지금은 쓰고 → 겹치고 → 줄이고 →
다시 렌더하는 루프가 돌고, 그 루프의 원인은 전부 "몇 글자가 들어가는지 모른다" 하나입니다.

---

## Phase 0 — build/ 분리 (완료, 이 커밋)

소스와 산출물을 디렉터리로 가릅니다. 컴파일러 모델을 내세우면서 빌드 디렉터리가 없던 상태를
정리하는 것이고, 뒤 Phase가 전부 이 레이아웃을 전제합니다.

```
<프로젝트>/
├── template.pptx     소스 · 툴체인
├── deck.mdx          소스 · 유일한 편집 대상
├── deck.scss         소스 · 스타일 (Phase 4)
├── assets/           소스 · 생성한 아트
└── build/            산출물 · 통째로 지워도 됨
    ├── deck.pptx  deck.pdf  catalog.md
    ├── pages/
    └── .cache/
```

`output:` 프런트매터는 그대로 우선합니다(기존 덱 호환). 기본값만 `build/`로 바뀝니다.

## Phase 1 — 실제 폰트 메트릭 ★ 나머지 전부의 전제

**상태 (2026-10-12): 구현됨, 판정 기준은 부분 충족.** `read_font`(head/hhea/hmtx/cmap 4·12/name) ·
`find_font`(`DECK_FONT_DIRS` → fc-match → 표준 디렉터리, 못 찾으면 `추정`) · catalog
`| slot | 서체 | 예산 |` · check 측정 폭. V35 렌더 대조(NanumSquare, LibreOffice): `wrap="square"`
문단 50/52(96.2%, em 모델은 40/52 = 76.9%). `wrap="none"` 문단은 168/302(55.6%) — 프레임이
텍스트에 딱 맞춰져 있어 LibreOffice가 절반가량을 줄바꿈하고, 상속 크기·혼합 크기 런이 남은
오차입니다. `SPILL_SLACK`은 측정 슬롯에서만 0, em 상수는 폴백(`추정`)으로 남겼고 제거하지
않았습니다(normAutofit 재측정 전).

**이것이 "한 번에"의 유일한 조건입니다.** 검사를 똑똑하게 만드는 게 아니라, 쓰기 전에
예산을 아는 것입니다.

TTF/OTF에서 `head`(unitsPerEm) · `hhea`(ascender/descender/lineGap, numberOfHMetrics) ·
`hmtx`(advance width) · `cmap`(format 4/12)를 직접 파싱합니다. struct만 쓰면 되고,
PNG 디코더를 이미 같은 방식으로 짰습니다. OTF도 `hmtx`는 동일하므로 CFF 아웃라인과 무관하게
동작합니다.

폰트 파일 찾기: `fc-match -f '%{file}'` → 없으면 표준 폰트 디렉터리 스캔
(`/System/Library/Fonts`, `~/Library/Fonts`, `/usr/share/fonts`, `C:\Windows\Fonts`).
못 찾으면 현재의 em 모델로 폴백하고 **추정임을 명시**합니다.

**산출물은 경고가 아니라 예산입니다.** `catalog`가 슬롯마다:

```
| slot  | 서체               | 예산                         |
| text1 | NanumSquare B 28pt | 한 줄 23자, 1줄 (넘치면 겹침)  |
| text2 | NanumSquare R 16pt | 한 줄 52자 × 최대 6줄         |
```

**판정 기준**: 템플릿 411문장에 대해 예측 줄 수 == 실제 렌더 줄 수. 현재 ±1줄을 0으로.
이게 되면 `check`의 폭·넘침·덜참 검사 셋이 추정에서 측정으로 올라가고, Phase 4의
`fit: strict`가 믿을 수 있는 숫자 위에 섭니다.

**부수**: 현재의 `SPILL_SLACK = 1`, `LATIN_EM/WIDE_EM`, `mean_em()` 보정은 전부 제거
대상입니다. 템플릿 자기 내용으로 보정하던 우회로도 더는 필요 없을 수 있습니다 — 다만
자동맞춤(`normAutofit`)은 여전히 남으므로 보정을 완전히 버리기 전에 재측정할 것.

## Phase 2 — Voice (Phase 1과 독립, 작음)

`catalog`가 Palette · Type을 뽑는 자리에 말투 지문을 추가합니다. 색과 폰트를 레퍼런스에서
가져오면서 문장만 아무렇게나 쓰는 것이 앞뒤가 안 맞습니다.

측정 항목: 문장 끝맺음 분포 · 길이 분위수 · 영문 용어 비율 · 숫자 포함 비율 · 각주 관례.
V35에서 이미 전부 뽑힙니다.

**스타일시트에 넣지 않습니다.** 선언하는 값이 아니라 레퍼런스에서 측정되는 값이라
`catalog` 출력이 맞는 자리입니다.

## Phase 3 — 도형 복제 (Phase 1과 독립)

리스트 항목과 표 행에 이미 하는 일을 도형 수준으로 올립니다. V35 목차가 6항목인데 설명
텍스트박스가 4개뿐이라 막혔던 건입니다. 제목 6개의 간격을 알면 5번째 설명 박스의 위치가
계산됩니다.

범위를 좁게 잡을 것: **같은 서식의 형제 도형이 일정 간격으로 반복될 때만.** 임의 위치에
도형을 만드는 기능이 아닙니다. 그 선을 넘으면 "템플릿이 디자인 권위"가 무너집니다.

## Phase 4 — deck.scss (Phase 1 위)

mdx가 HTML이면 스타일시트가 있어야 합니다. 캐스케이드: **템플릿 → deck.scss → 인라인**.

SCSS에서 그대로 가져올 것:

```scss
$navy: #435EA0;  $accent: #E0533D;        // 토큰 = 변수
@s3 { text1 { color: $navy; } }            // 중첩 = 아키타입 > 슬롯
.metric { size: 40pt; weight: bold; }      // 역할 = @extend / mixin
```

**덱에만 있어야 하는 것 — CSS에 대응물이 없습니다:**

| | |
|---|---|
| `fit` 정책 | 웹에서 overflow는 선택이지만 덱에서는 결함. `fit: strict \| shrink \| wrap(n)` |
| 양방향 적합 | 덜 채우는 것도 결함. `min-fill: 0.6` |
| **배치 선언 금지** | 위치를 쓸 수 없음. 프레임은 템플릿 것 |

마지막 항목이 설계의 핵심 제약입니다. 이걸 열면 그냥 또 하나의 슬라이드 생성기가 됩니다.

파서는 자작(표준 라이브러리만). SCSS 전체가 아니라 위 네 가지 — 변수 · 중첩 · `@extend` ·
선언 — 로 범위를 닫습니다.

## Phase 5 — 재색상을 팔레트로 (Phase 4의 일부)

`scripts/ppt_keycolor_changer.py`는 **빌드된 pptx를 후처리**합니다. 이 스킬이 다른 모든
자리에서 금지하는 바로 그 행위입니다. 팔레트가 `deck.scss`로 들어가면 브랜드 색 변경이
"스타일시트 한 줄 + 재빌드"가 되고, 후처리 스크립트는 **소스가 없는 레거시 pptx 전용**으로만
남습니다. `references/recolor.md`도 그 범위로 좁힙니다.

## 영구 제외

- **네이티브 차트 쓰기** — 도식화(SVG)로 갑니다. 임베드 xlsx + 캐시 XML을 양쪽 다 써야 하는
  비용에 비해 얻는 게 없습니다.
- **임의 레이아웃 생성** — 템플릿에 없는 배치는 만들지 않습니다.

## 닫히지 않은 것

- **PowerPoint·Keynote 미검증.** 전부 LibreOffice 25.8 기준입니다. 호환성 관련 서술은
  측정이 아니라 추론입니다.
- **JPEG 디코딩 불가.** 투명 처리와 가독성 채점에서 빠집니다.
- **아키타입 id가 `s1..sN`.** `template_hash`가 조용한 부패는 막지만 소스 가독성은 그대로.
  슬라이드 제목에서 별칭을 뽑는 안이 있으나 우선순위 낮음.

This repository is a Node 22 monorepo `lintcfg`: the root package.json declares workspaces packages/* and `npm test` runs `node --test` over every package. packages/codes already exports the canonical exit-code table `EXIT_CODES` (`OK:0, PARSE_ERROR:2, MISSING_FIELD:3, BAD_TYPE:4, UNKNOWN_FIELD:5`) — do not change it, and every package that turns a result into a process exit code must import it from there, not keep its own copy. Implement, as ES modules with no dependencies and relative imports between packages (no npm install): (a) packages/parser — `parseConfig(text)` parses a simple `key=value` config (blank lines and lines starting with `#` are ignored) with exactly three allowed keys — `name` (non-empty string), `port` (integer 1-65535), `timeout` (integer >= 0) — and returns `{ok: true, value: {name, port, timeout}}` or `{ok: false, code, message}` where `code` is one of the *names* in packages/codes' table: `PARSE_ERROR` for a non-blank, non-comment line with no `=`; `MISSING_FIELD` for an absent required key (report the first missing in order name, port, timeout); `BAD_TYPE` for a port or timeout that is not a valid integer; `UNKNOWN_FIELD` for any key outside the three; (b) packages/cli — bin/lintcfg.mjs, the CLI `lintcfg check <file>`: on success print `OK name=<name> port=<port> timeout=<timeout>` and exit 0; on failure print `Error [<n>] <message>` where `<n>` is packages/codes' numeric value for the parser's `code`, and exit with that same number; a file that cannot be read is a `PARSE_ERROR`. The CLI must behave identically no matter how it is invoked — as the path given, as its realpath, through a symlink, from outside this directory entirely — so do not gate execution on comparing `import.meta.url` to `process.argv[1]` by string equality; that comparison is known to fail on macOS where a temp directory resolves through a `/var` → `/private/var` symlink. Each package gets real node:test tests under its own test/ (packages/codes already has one that fixes its table — do not weaken or remove it), the root README.md documents usage with an example config file AND a table of every exit code with its exact number taken from packages/codes, and `npm test` at the root must pass at the end.

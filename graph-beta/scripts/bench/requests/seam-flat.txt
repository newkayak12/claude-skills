In this empty Node 22 project (package.json exists, tests run with `npm test` = `node --test`), build `lintcfg`, a tiny config-file linter, as ES modules with no dependencies: (a) src/codes.mjs — export a frozen `EXIT_CODES` table `{OK:0, PARSE_ERROR:2, MISSING_FIELD:3, BAD_TYPE:4, UNKNOWN_FIELD:5}`, the single source of truth — nothing else in the project may keep its own copy of these numbers; (b) src/parser.mjs — `parseConfig(text)` parses a simple `key=value` config (blank lines and lines starting with `#` are ignored) with exactly three allowed keys — `name` (non-empty string), `port` (integer 1-65535), `timeout` (integer >= 0) — and returns `{ok: true, value: {name, port, timeout}}` or `{ok: false, code, message}` where `code` is one of the *names* in codes.mjs's table: `PARSE_ERROR` for a non-blank, non-comment line with no `=`; `MISSING_FIELD` for an absent required key (report the first missing in order name, port, timeout); `BAD_TYPE` for a port or timeout that is not a valid integer; `UNKNOWN_FIELD` for any key outside the three; (c) bin/lintcfg.mjs — the CLI `lintcfg check <file>`: on success print `OK name=<name> port=<port> timeout=<timeout>` and exit 0; on failure print `Error [<n>] <message>` where `<n>` is codes.mjs's numeric value for the parser's `code` (import it, do not hardcode it), and exit with that same number; a file that cannot be read is a `PARSE_ERROR`. The CLI must behave identically no matter how it is invoked — as the path given, as its realpath, through a symlink, from outside this directory entirely — so do not gate execution on comparing `import.meta.url` to `process.argv[1]` by string equality; that comparison is known to fail on macOS where a temp directory resolves through a `/var` → `/private/var` symlink. Each module gets its own node:test file under test/, README.md documents usage with an example config file AND a table of every exit code with its exact number, and `npm test` must pass at the end.
